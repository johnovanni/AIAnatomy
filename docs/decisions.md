# Decisions

- **D1** Tensors store `double`, not `float`. Finite-difference gradient checks are then exact enough to trust, and the speed cost is small for scalar C#. Lesson text notes that real models use 16- or 32-bit numbers.
- **D2** A WPF-free `AIAnatomy.Presentation` project holds the view-models, so they can be unit-tested. This refines the spec's App -> Lessons chain to App -> Presentation -> Lessons.
- **D3** Pre-layer-norm blocks as in GPT-2 (`x + Attn(LN1(x))`, then `x + FF(LN2(x))`, then a final LN), with a separate (untied) output matrix, which is easier to explain as "the output layer".
- **D4** The BPE tokenizer works on characters, not bytes, so its pieces stay readable. Words are pre-split with the leading space attached (" the"), as in GPT-2.
- **D5** "Rules vs. learning" task: predict the next letter. A readable list of hand-written rules is compared with a bigram model (a table of next-letter scores) that learns from the fables in a few seconds.
- **D6** The Family and Beyond tabs exist in Stage 1, each showing a "Coming in a later stage" page that lists what it will contain.
- **D7** The training text is *Aesop's Fables* (George Fyler Townsend translation, Project Gutenberg eBook #21, public domain in the US). The Project Gutenberg header, footer and licence are removed, as their terms require when the trademark isn't used. Downloading it needs the owner's okay (asked at plan review). If it is refused, the builder writes 40 short original fables instead.
- **D8** Each forward pass works on one sequence (`[T, D]` tensors). The loss of a training batch is the mean of the B sequence losses (gradients are summed over the sequences, then divided by B). This keeps traces simple to show.
- **D9** `GradCheck.MaxRelativeError` runs on parameter copies of its inputs (so callers may pass plain tensors) and measures |analytic - numeric| / max(1, |analytic|, |numeric|), so near-zero gradients do not inflate the error. `Backward()` clears intermediate (non-leaf) gradients before propagating; leaves keep accumulating until `ZeroGrad()`.
- **D10** Tokenizer details (controller rulings, Task 5): `CharTokenizer` vocabulary is `IReadOnlyList<char>`, so only BMP characters can be in it; any other scalar (emoji) is unknown (id 0) and counts as one token. BPE words start at every space and end at the next space or newline; a newline is its own piece; merges never cross a word. BPE ties go to the pair seen first in the text. BPE ids are unknown (0), base characters in ordinal order, then one id per merge in learned order; encoding applies merges by id and rank, so two merges producing the same text stay distinct. `TextNormalizer` only turns `\r\n` and lone `\r` into `\n`.
- **D11** Transformer parts live in namespace `AIAnatomy.Models.Transformers` (plural, folder `Transformer/`): a namespace named `Transformer` clashes with the class `Transformer`. Attention biases are named `query_bias`, `key_bias`, `value_bias`; the multi-head projection is `blocks.N.attn.output` / `output_bias`; the feed-forward is `ff.in`, `ff.in_bias`, `ff.out`, `ff.out_bias`; the final norm is `final_norm`. `Transformer.Clone` builds a fresh model and copies weights in `Parameters()` order. A switched-off head returns a zero tensor, so no gradient flows to that head. The "positions removed, swap tokens 0 and 1" invariance holds exactly for one layer only (with more layers the causal mask makes positions 0 and 1 see different things), so the test uses one layer.
- **D12** Training details (Task 7). The global gradient norm is clipped to 1.0 before every Adam step (standard practice; it keeps early steps from jumping). The learning rate is constant. The loss is checked after every batch, before the Adam step, so a diverged step never changes the weights; the step is still counted and reported. Each batch sequence runs on its own thread with its own copy of the weights (slot 0 is the model itself); their gradients are added in sequence order, so results do not depend on thread timing or core count. Validation windows come from the last 10% of the text (if that is shorter than one window it grows backwards just enough to hold one), at most 32, chosen with the seed.
- **D13** `Sampling.Generate` returns only the newly written text, not the prompt. An empty prompt starts from a newline, or from the unknown token if the vocabulary has none. Probabilities are built in the order temperature, top-k, top-p, each renormalised; top-p keeps the smallest set of top choices whose total reaches p.
- **D14** Model files (Task 7): header is one JSON line (camelCase names, enums as text) with the config, vocabulary, info and every parameter's name and shape; then little-endian 64-bit floats. Loading checks format, version, config size limits, every name and shape, the exact byte count and that every number is finite; any problem is an `InvalidDataException` with a plain message. A library entry's name is the model's own name (or the file name if unreadable); saving writes through a `.tmp` file and then renames, so a failed save never leaves a half-written model. Shipped models are always returned with `IsShipped` true.
- **D15** `Ops.MatMul` loops i-k-j over spans with 4-wide vector adds and runs output rows on several threads once N*K*M exceeds 200,000. Every output element is still summed in the same order as a plain loop, so results are bit-identical with or without threads.
- **D16** Induction experiment (Task 8, ruling R16). The first design (8 random tokens then the same 8 again) is exactly periodic, so a learned-position head that looks 7 back solves it in layer 1 and no induction head forms (loss reached its floor by step 200; layer-2 scores stayed under 0.1). Training and scoring now use 17-token sequences: a random prefix, a segment of L distinct letters (L 4..8), the same segment again, random filler; prefix and filler never use the segment's letters, and the prefix length varies, so only matching by content works. `InductionScore` averages attention from second-copy position SecondStart+j to FirstStart+j+1 (positions up to 15); `PreviousTokenScore` is a diagnostic for the earlier-layer previous-token head. Choices: config unchanged (width 32, 2 layers, 2 heads, learned positions, attention-only), batch 16, learning rate 3e-3, 1,500 steps, seed 1. Result in Release: 19 s; layer-2 induction scores 0.82 and 0.90; layer-1 previous-token scores 0.40 and 0.23. The slow test runs in Release.
- **D17** Trainer windows (Task 8, R14). A window of n+1 tokens means n inputs and n targets shifted by one, so sources may give windows shorter than ContextLength+1. `CorpusBatchSource` keeps the old corpus rules and RNG order.
- **D18** Teaching toys (Task 9). Perceptron weights and bias start at zero and `Train` restarts from zero each call; one epoch is recorded per pass and training stops after the first pass with no errors. `LossSurface.Descend` returns the start point as entry 0 (steps + 1 entries). `ExpressionGraphDemo.Run` rebuilds the graph each time, so repeated runs give identical gradients. `RuleBasedWriter` has 10 rules, the last ("Otherwise, write e.") always applies; `Write` returns only the new text. `BigramModel` starts from an all-zero table (uniform), so its seed is stored but unused; it trains by full-batch `Sgd` on all adjacent pairs and generates at temperature 1. The shared 2 KB test prose moved to `TestTexts.Fable`.
- **D19** Training text and shipped models (Task 10). `content/texts/aesop-fables.txt` is Project Gutenberg eBook #21 (Townsend), body only: from the "AESOP'S FABLES" heading to the end of the last fable ("The Brazier and His Dog"); the Gutenberg header/footer/licence, contents, preface, Life of Aesop, footnotes and index are removed. Normalisation: "\n" line endings, curly quotes and apostrophes made straight, trailing spaces removed, runs of 3+ blank lines collapsed to 2. Nothing else changed, so the text keeps 3 non-ASCII characters (an em dash, "AE" and "ae" ligatures); 190,005 characters, 69 tokens with the unknown token. Source and edits are in `THIRD-PARTY-NOTICES.txt`.
- **D20** Shipped models (Task 10), built by `tools/AIAnatomy.Pretrain` in Release with seed 1. Fables model: default `TransformerConfig` (113,093 parameters), batch 8, learning rate 3e-3, **3,000 steps in 517 s** (about 0.17 s/step on this machine); train loss 1.53, **final validation loss 1.711** (below 1.9 from about step 1,600). Induction demo: `InductionExperiment.TrainAsync` with its 1,500 default steps, 21 s, best layer-2 induction score 0.904 (layer-2 head 1: 0.816); both well over the 0.6 needed. Names: "Fables model" / "Aesop's Fables (Townsend)" and "Induction demo" / "Repeated letter sequences". Both files are saved with `IsShipped` true and are under 1 MB (887 KB and 82 KB); the fables file's `ValidationLoss` is the trainer's last periodic validation (step 3,000, a multiple of 25).
- **D21** Test hygiene (Task 10, R18). `TrainerTests` and `InspectionTests` (everything that trains) share the xunit collection "Training" with parallelisation disabled, so timing assertions are not disturbed by other tests. In Debug the induction slow test is skipped with a message that names the Release command; `README.md` has a "Running the tests" section. The Models test project copies `content/**` to its output folder, like ASLCoach.
- **D22** Source citations (Task 11): `content/sources.json` holds 12 entries written from memory of the standard references; arXiv/DOI links only where certain, otherwise null (radford2019). `nostalgebraist2020` is cited as a LessWrong post and `suttonbarto2018` as the book (also used for Q-learning, not Watkins 1989). D-number: citations to be re-verified in Task 20.
- **D23** Lessons (Task 11): `sources: textbook` is reserved for standard textbook material; it is not looked up in sources.json and sets `Lesson.IsTextbookMaterial`, with `SourceIds` excluding it. The Markdown parser is lenient: headings, bullets and `$$` blocks also end a running paragraph; an unclosed `$$` is plain paragraph text; bold and italic need non-space text next to the markers, so `2 * 3 * 4` stays literal. `Order` is 1-based within a section; file names are `<nn>-<id>.md`.
- **D24** Presentation (Task 12). `MainViewModel` builds its own `LabFactory` and passes its `NavigateToLesson` as the navigate callback, so there is no construction cycle; the registry is exposed as `MainViewModel.Labs` so tests (and later App start-up) can register labs. A lesson whose lab is not registered shows `ComingLaterLabViewModel` ("This lab is being built."). `SettingsService.Save` updates `Current` even if the disk write fails (IO/permission errors are swallowed: settings are a convenience). A non-finite body size becomes 20; a blank `ActiveModelName` becomes null. Heading size is rounded half away from zero (22.4 to 22, 28 to 28, 44.8 to 45). `MainViewModel.RefreshModelEntries()` re-reads the library after saves and deletes. Selecting a lesson only refills `Lessons` when the section changed. `NavigateToLesson` throws `KeyNotFoundException` for an unknown id (from `LessonCatalog.Get`).
- **D25** Shell and controls (Task 13). Text sizes in settings are points; ThemeManager converts them to WPF pixels (1 pt = 96/72 px, as in ASLCoach) and also sets SmallFontSize (body x 0.85, at least 16 pt), SubheadingFontSize (body x 1.15) and FormulaScale (body x 1.1). Settings and Sources are pages that replace the lesson (MainViewModel `IsShowingSettings`, `IsShowingLesson`); `OpenLesson`/`ShowSection` on the already-selected item just go back to the lesson, so the lab is not recreated. `SettingsViewModel` keeps the size to whole points and saves on every change. Numbers on screen go through `Presentation.Visuals.NumberText`: `Exact` is the shortest round-trip text of the double (readouts, tooltips), `Short` (3 decimals, whole numbers without decimals) is for labels inside charts and line-chart legends (changed 2026-11-24, see the AA-001 entry below), `Tick` for axes, `Percent` two decimals; minus signs are U+2212. The heat-map ramp is the same light-to-dark blue in both themes (it is a figure); text inside a square is black or white, whichever contrasts more (at least 4.58:1). `GridCell(Row, Column)` was added to Visuals for `HeatMap.SelectedCell`. Every control draws a readout or legend with the exact value, so colour, shape (scatter groups), dash style (line series), outline plus "chosen"/"current step" tags carry meaning together. NetworkDiagram node X/Y are fractions (0..1) of its size; its text shrinks (to 60% at most) until no boxes overlap. Charts without a set height grow with the text size (at least 14 lines). MarkdownView draws bullets as text with a hanging indent because WPF list markers stayed black in the Dark theme. Lesson links and linked diagram boxes raise one bubbling routed event (`LessonNavigation.NavigateRequestedEvent`) handled once by MainWindow. `--render-png` defaults to Light at 20 pt (not the user's settings) so pictures are reproducible, uses in-memory settings so nothing is saved, never shows the window (lays out its content on its own), and draws the gallery at its full height. `--selftest all-labs` works now; `--selftest train` exits 1 with "needs the Train lab" until Task 18.
- **D26** Task 13 review fixes. The lessons list always stays in the left column; Sources, Settings (and the lab plus explanation) share columns 2 to 4. Pane scroll areas (lab, explanation, Sources, Settings, gallery) are tab stops with a focus ring (`PaneScroller` style). A keyboard-focused link becomes a solid focus-coloured block. Axis maths moved to `Presentation.Visuals.AxisTicks` (tested): ticks are computed from their index and capped at count·3 + 2; ranges are widened only when their ends are equal within 1e-9 of their size (`Widen`), and `Pad` adds 5% after that; the line chart's x axis uses `Widen` only. `NumberText.Short` keeps a single parameter (a second, optional one let `Select(NumberText.Short)` pass the index as the number of decimals); `ShortWithDecimals` is separate. Heat-map squares may grow past 96 px to fit a three-decimal number, and fall back to two decimals before leaving the number out. Network arrow labels are drawn after the boxes, moved sideways off the arrow until they touch no box. Unexpected errors (`DispatcherUnhandledException`) are appended to `%LOCALAPPDATA%\AIAnatomy\error-log.txt` and shown in a plain window ("Something went wrong: … Your settings and models are safe."); the app keeps running (diagnostic runs exit 1). `--render-png` accepts several views separated by commas (files "name-view.png"), each rendered with fresh services; radio buttons no longer use a GroupName, which linked them across windows.
- **D27** Task 14 labs (R19, N1). The Rules vs. learning lab trains the bigram model with plain gradient descent at **rate 20** in 20-step chunks (20 chunks per press of Learn, Stop between chunks). Measured on the fables: loss 4.23 (uniform) to 3.07 after one chunk, 2.52 after ten, 2.46 after twenty; at rate 3 the text still looked like noise after 20 chunks, at rate 10 it was only half-way. The loss falls on every chunk at 20 (tested). The corpus is the first 6,000 characters of the fables so a chunk stays well under a second in Debug. `BigramModel` is unchanged; a Models test checks P('h'|'t') beats uniform and is above 0.3. The Tokens lab uses a character tokenizer built from the fables (the same characters as the fables model) and a BPE learned from the whole fables text, once per merges value (cached), on a background thread after a 250 ms debounce. The Position lab reads the model's position vectors from the trace of a forward pass over a full-length dummy text, and its on-screen note says removing positions takes away the direct order signal while deeper causal models can still leak order through the mask (N1). Architecture map omits the Feed-forward box for models without feed-forward layers (the induction demo). `LabViewModel` gained `Deactivate`, `OnSeedEdited` and `WorkCompleted` (the PNG diagnostic waits for it); `HeatMap` writes only every few-th row/column label when the squares are too small; a shared `TextBox` style was added to the theme.
- **D28** Task 15 labs (R16, N3, N4). Embeddings: untrained model = fresh `Transformer` with the active config and a lab Seed that starts at the model's own `Info.Seed` (changeable, Reset restores it); one selected token is shared by both pictures. Attention toy: vectors are `DragHandle`s clamped to ±3, dragged on a new minimal `DragPlot` control (snaps to 0.05; arrow keys, Shift for bigger steps, Page Up/Down to pick a point) and typed in number boxes (commit on leaving or Enter); softmax's e^score column is shown with `Math.Exp` for display only, the weights come from `Ops.SoftmaxRows` (tested to agree). Real heat maps pass NaN above the diagonal so `HeatMap` shows "blocked". `HeatMap` gained `OutlinedCells` (heavy outline, not colour) for the R16 induction squares. `InductionExperiment.TrainAsync` gained an optional `modelCreated` callback: it is the only way to read the model while it trains; the lab's `IProgress` runs on the trainer thread between steps, measures scores every 100 steps there (safe, nothing is changing), and posts results to the UI thread; loss is charted every 10 steps. The Attention lab opens with the trained demo already shown (so the induction section is informative at once, and renders can be checked); the demo is loaded through `Library.Load` and never becomes the active model. Seed on the Attention lab picks the example sequence, the scoring sequences and the training start.

## Task 17 (Sampling and Learning labs)

- The Learning lab shows its four parts as sections one under the other, not tabs, so nothing is hidden behind a tab and a rendered picture shows all four. Each part is its own view-model (`PerceptronPanelViewModel`, `LossPanelViewModel`, `GraphPanelViewModel`, `CrossEntropyPanelViewModel`) inside `LearningLabViewModel`; no randomness is used there, so it has no Seed box.
- Sampling lab: "Sample 100 times" restarts `SeededRandom(Seed)` each press, so the same seed gives the same counts; changing the text, a setting or the seed clears old samples and writing. The bars and score list show the 15 highest-scoring characters; the full probability array is kept for sampling. "Generate 200 characters" runs on a background thread and a changed setting drops its result.
- Perceptron: "Step one epoch" retrains from zero for one more epoch (`Perceptron.Train` always restarts), which gives the same weights as carrying on. Choosing a rule sets the epoch limit to its default (20, or 100 for XOR); changing rule or rate clears the epochs. The decision line is drawn only inside the square -0.25..1.25 (after epoch 1 of AND it lies outside, and the line text says so). The epoch table shows the last 20 epochs.
- Loss surface: 30 steps from (-4, 1.5). "Too large" is shown when the loss at the last step is above the loss at the step before (rate 0.1 exactly gives a constant w2 loss, so it is not flagged; 0.101 is). The contour plot is a new control, `ContourPlot` (shaded grid, marching-squares contour lines with values written on them, a dashed path with a square start and a diamond end). `ScatterPlot` gained a `Lines` property (dashed, named in its legend, the axes fit its end points) for the decision line.
- Expression graph: the four numbers are limited to -100..100 and not-a-number becomes 0. Node boxes show "value ... / gradient ..." on two lines, and the exact numbers are repeated in a table under the diagram.
- Cross-entropy: the places are the first N-1 tokens (each needs a next character), numbered from 1; p is read from `Sampling.Probabilities` at temperature 1; one character of text is not enough and says so.

## Task 18 (Train lab, self-tests)

- **Speed of the defaults, measured in Release** (a throw-away console harness calling `Trainer.Step` and, every 50 steps, `Sampling.Generate` for 200 characters, as the lab does): fables text, width 32, 2 layers, 4 heads, context 64, feed-forward 128, batch 8, learning rate 3e-3, seed 1 (32,005 parameters). 600 steps took **38.9 s** in all: 31.4 s of training (about **19 steps per second, 52 ms per step**) plus 7.5 s for the 12 samples (about 0.6 s each), so the lab shows about 15 steps per second overall. Loss fell from 4.23 (step 1) to 2.70 by step 50 and to a validation loss of 2.26 at step 600; the samples went from random characters ("C(RmeOKy(d|CH-geEcii…") to letter patterns with short words ("…you me yomeipe he hin wawhe…"). That is well inside the 2-minute aim, so the controller's defaults were kept. A Debug build is slower.
- The lab never trains the active model: Start builds a fresh `Transformer` from the boxes (the default) or a `Clone()` of the active model. "Carry on training" is offered when every character of the chosen text is in the active model's vocabulary (a subset, not only an identical vocabulary), because the text is then encoded with that model's own tokenizer without any unknown tokens; this also lets a fables model carry on with pasted text that uses only its characters. When carrying on, the shape boxes are not used (they are disabled) and the saved `StepsTrained` is the model's earlier steps plus this run's.
- Every box is typed text, read after every key (invariant culture, "3e-3" accepted). Ranges: layers 1–4, heads 1–8 and dividing the width, width from {16, 32, 48, 64, 96}, context 16–128, learning rate above 0 and at most 100 (high enough to show divergence), steps 1–100,000, batch 1–64; every problem is listed, one per line, in place of the Start button, under the text problem ("Type some text to begin" for an empty pasted text). The text is checked by its length in tokens as the model reads it (`CorpusValidator.ProblemForLength` on the encoded length), not by the typed string: the text box gives "\r\n" for Enter, which the tokenizer reads as one new line, and any character outside the Basic Multilingual Plane (such as an emoji, two UTF-16 units) is one unknown token (D10). The "N characters" summary counts the same way. Pasted text of 50,000 characters or more is tokenized on a background thread ("Reading your text…" stands in for Start meanwhile). The text box has MaxLength = `CorpusValidator.MaxCharacters`, and a paste that would go over it is refused as a whole with the validator's message (the box would otherwise cut it short silently). Settings are disabled while a run is going on or paused. Feed-forward width is always 4 × width.
- Review round 1 (R33): the form (text, shape, settings, parameter count, text summary) is its own view-model, `TrainSettingsPanelViewModel` (`TrainLabViewModel.Settings`), as the Learning lab does with its panels; the run controller (training, samples, speed, saving) stays in `TrainLabViewModel`. Start is disabled while a run is paused (Stop first), so a paused model is never discarded without the user ending it; Resume is disabled while a save is reading the weights. The validation loss next to the current step says when it was measured ("(measured at step 25)"). The step that diverged is not drawn on the chart. Changing the name clears an open overwrite question. A failure while building the model or trainer shows a plain sentence and leaves training off. The seed note and the feed-forward note describe the active model when carrying on from it (its own feed-forward width, or "no feed-forward layers").
- The parameter count is read from `ParameterCountsByPart()` of a freshly built model of the chosen shape (cached per shape), listed in the fixed part order (R12).
- Reports are queued on the trainer thread and applied on the UI thread in order; the queue is emptied once more when a run ends, so no report is lost or applied after a newer run started (a generation number guards Pause/Stop/Deactivate/Reset). The loss chart keeps at most about 1,000 training-loss points (every k-th step for long runs) and every validation point (every 25 steps). Speed = steps since this run (or resume) began ÷ time since then, so it includes the samples; shown as "about N steps per second; about M seconds left".
- Samples: every 50 steps, 200 characters from an empty prompt (a new line), temperature 1, always with `SeededRandom(seed)`, so only the model changes between samples. Newest first, newlines shown as ↵.
- Saving: `ModelLibrary.PathFor(name)` (new) is the exact file `Save` writes, and the overwrite question appears whenever that file exists, even under a different name ("a/b" and "a_b"). Shipped model names are refused (case-insensitive). `ModelLibrary.Save` refuses any non-finite weight with "This model has numbers that are not finite, so it can't be saved." The save runs on a background thread after the trainer has stopped; "Use in the labs" then calls `SetActive` back on the UI thread, and skips the save when the model is already saved, unchanged, under that name. `LabFactory` gained an optional `libraryChanged` callback (MainViewModel passes `RefreshModelEntries`) so a plain save also shows in the model picker.
- Diagnostic runs (`--selftest`, and now `--render-png` too) use `AppServices.Create(settings, folder)` with an empty temporary user-model folder that is deleted afterwards, so they never read or write the user's models. `--selftest all-labs` also calls `Deactivate`, waits for each lab's `WorkCompleted`, and fails (listing them) if a lesson names a lab that is not registered — until Task 19 registers StepThroughLab and ScaleLab it therefore exits 1 after checking every other lab. `--selftest train` opens the Train lab with its defaults, trains 5 steps through the view-model and exits 0 only if 5 reports with finite losses arrived.

## Task 19 (Step-through and Scale labs)

- Step-through: the heads stage lists, for each head, the 5 largest attention weights at the chosen token (labelled "head 2 looks at 3:e"), not every weight; with a context of 64 and several heads, every weight would be hundreds of lines. The feed-forward stage ranks neurons by absolute value (the sign is kept in the value) and numbers them from 1. The tokens stage lists every token with its id and marks the followed one. Logits are shown as the full row; probabilities as the 10 largest (temperature 1, `Sampling.Probabilities`). Previous/Next buttons and the arrow or Page keys (when the steps have focus) move the "current step" marker; the view scrolls to it.
- Scale: our count is the sum of `ParameterCountsByPart()` listed in the R12 order (equal to `TransformerConfig.CountParameters()`, tested). The log axis starts one power of ten below our count and ends at 10^12, so every bar is visible; the sentence under the chart uses the real counts ("GPT-3 has about N million times as many parameters as this model") and says nothing about Claude's size.

## Task 20 (Lesson texts, Sources, scientific inconsistencies)

- **Formula test project (R6).** `XamlMath.Shared` 2.1.0 alone cannot parse the lessons' formulas: commands such as `\log`, `\exp`, `\tanh`, `\ldots` and the `\,` and `\;` spaces are "predefined formulas" that only WpfMath registers (the shared `TexPredefinedFormulaParser` is internal). So `EveryFormulaParsesInWpfMath` lives in a new Windows-only project, `tests/AIAnatomy.App.Tests` (`net10.0-windows`, WPF, WpfMath 2.1.0, references Lessons only), added to the slnx. It parses every `$$` block with `WpfTeXFormulaParser.Instance` (as `MarkdownView` does) and also renders it to a bitmap on an STA thread, so render-time failures are caught too. WpfMath does not know `\quad` or `\qquad`; the lessons use `\;` spacing or separate formula lines instead. `\text{}`, `\mid`, `\le`, `\infty`, `\bar`, `\hat`, `\top`, `\leftarrow` and `\partial` all work.
- **Lesson length and Markdown checks.** Besides the brief's four tests, `LessonContentTests` holds the controller's tone sizes (explanation 150–350 words, "Brains and models" note 60–150 words), checks that no lesson shows a literal `*`, `[`, `](`, `$$` or `##` (nested or unclosed markers), and checks that the two coming-later lessons are lists without formula or note. Word counts ignore formulas and count tokens that contain a letter or digit.
- **Sources are named in the text.** The explanation pane does not list a lesson's front-matter sources, and the Sources page says textbook material "is marked in each lesson". So every lesson cites inline ("(Vaswani et al., 2017)") and ends its explanation with an italic "Sources: …" line, and the front matter lists `textbook` too when the lesson also rests on textbook material (almost all do). A test checks that each cited source's first author appears in the lesson's text and that textbook lessons say so.
- **Optional sections.** Every Parts and Whole lesson has a formula section. Of the Map lessons, Rules versus learning has one (the bigram softmax, loss and update) and the Architecture map does not (the full chain is in Step through a prediction). Every lesson except the two coming-later pages has a "Brains and models" note. The test for missing sections now uses `family-coming`.
- **Numbers quoted in lessons** are from the shipped Fables model and the labs' defaults (D20, Task 18): 69 tokens, width 64, 2 blocks, 4 heads, context 64, feed-forward 256, 113,093 parameters (58% in the feed-forward layers); Train defaults 32,005 parameters, 600 steps, about 39 s in Release here. "By 50 merges, ' the' and ' and' are single tokens" was measured with `BpeTokenizer.Train` on the fables (0, 50, 200 and 500 merges) in a throw-away test that was deleted. The GPT-2 small count 124,439,808 was computed from the published shape and the released code (tied output layer, feed-forward 4 × 768).

- **Tanh, reshape, convolution and pooling (Stage 2B, Task 3).** Conv2d is done by unfolding (im2col): each image becomes a [C*k*k, Hout*Wout] matrix and is multiplied by the weights with the same fixed-order row kernel MatMul uses, so the engine has one product to trust and gradient-check. Weights are [F, C*k*k]; row f is filter f, laid out channel, then ky, then kx. Stride 1, zero padding, output [N,F,H+2p-k+1,W+2p-k+1]. Backward folds the column gradient back (col2im), adding where windows overlap. Determinism: images are processed in parallel, but each image is independent and summed in a fixed order; the weight gradient is computed per image and then added in image order, and the bias gradient is summed sequentially, so results are bit-identical run to run. MaxPool2d uses non-overlapping windows and throws when H or W is not divisible by the size; on a tie the first maximum in row-major order takes the whole gradient. Reshape copies the data (so a later in-place change cannot reach the original) and passes the gradient straight through. All four are gradient-checked to 1e-6.

- **The memory network (Stage 2B, Task 9).** `ElmanRnn` (src/AIAnatomy.Models/Recurrent) is a plain Elman network (Elman 1990) with tanh: h_t = tanh(x_t W_in + h_{t-1} W_rec + b), h_0 = 0, logits_t = h_t W_out + b_out. Parameters, in this order: `input.weight` [V,H], `recurrent.weight` [H,H], `hidden.bias` [H], `output.weight` [H,V], `output.bias` [V]. x_t is one-hot, so x_t W_in is done as a row lookup (`Ops.Rows`). `Forward` runs B sequences of equal length side by side and returns every step's memory (`Hidden[t]`, [B,H]) and the logits [T*B,V] in position-major order (row t*B + b), stacked with existing ops (transpose each memory, `ConcatColumns`, transpose back), so Core is unchanged. `Step(previous, ids)` and `Logits(hidden)` are public for sampling and the hidden-state screen; `FromWeights(config, tensors)` wraps given tensors as the parameters (used by the gradient check and by `Load`). **Initialisation** (my call, not the transformer's 0.02): input rows std 1 (a one-hot input has a fan-in of 1), recurrent and output weights std 1/sqrt(H) (fan-in H), biases 0. tanh already bounds the memory to [-1, 1], so the memory itself cannot blow up; what the recurrent matrix governs is how signals and gradients change as they pass through time. - **Diffusion on 2-D points (Stage 2B, Task 10).** DDPM (Ho et al. 2020) on points, in src/AIAnatomy.Models/Diffusion. *Schedule:* `NoiseSchedule(100, 1e-4, 0.1)`, linear betas from t = 1 to t = 100 (as numpy.linspace in Ho et al.'s code), AlphaBar(t) the running product of 1 - beta, AlphaBar(0) = 1; AlphaBar(100) is about 0.0056, so at t = 100 a circle's mean squared radius is 0.0056 * 0.64 + 0.9944 * 2, about 1.99 (the test's "near 2" follows from the maths). *Network:* `DiffusionNet`, [x, y, 16 time features] (18 inputs) -> 128 -> 128 -> 2, ReLU after both hidden layers, nothing after the output; it predicts the noise e. - **Respacing and its source (Task 10).** `NoiseSchedule.Respaced(S)` follows Nichol and Dhariwal (2021), section 4 ("Improving Sampling Speed", equation 19): sample on a subsequence of the training steps, with beta'_i = 1 - AlphaBar(t_i) / AlphaBar(t_{i-1}) and AlphaBar(t_0) = 1, so the respaced AlphaBar at step i is the original AlphaBar(t_i); the network is shown the original t. *One difference, chosen:* the paper takes S evenly spaced real numbers from 1 to T inclusive and rounds them (for S = 10, T = 100: 1, 12, 23, ..., 100); here t_i = round(i * T / S), i = 1..S (10, 20, ..., 100), which the brief asks for. Both are evenly spaced and end at T; ours spaces the first step like the rest instead of starting at t = 1. Respacing always draws from the full schedule. The paper's learned variances are not used: sigma'^2 = beta'.

- **Digit preprocessing (Stage 2B, Task 8), `DigitImage.FromStrokes`.** *Method:* UCI's page says NIST's programs extracted normalised 32x32 bitmaps and "32x32 bitmaps are divided into nonoverlapping blocks of 4x4 and the number of on pixels are counted in each block", giving 8x8 values 0..16; so the strokes are drawn onto a 32x32 binary bitmap, each 4x4 block counted and divided by 16 (DigitSet's training pixels are v x 255 / 16, then 0..1). Only `imageSize` 8 is supported; any other size (including the brief's default 28) throws `NotSupportedException`, and the app calls it with 8. *How NIST sized and centred the 32x32 bitmaps is not on the UCI page*, and NISTIR 5469 (the NIST form-based handprint system) is a scanned PDF that could not be read here, so the rule was **matched empirically** to the 3,760 bundled training digits (measured 2026-11-25 from `digits-train.bin.gz`, in the 8x8 grid): ink height 8 squares in all 3,760 (every image touches the top and bottom rows); ink width 6 squares in 76% (2875), 5 in 436, 7 in 336, 4 in 106, 8 in 5, 2 and 3 in one each (median 6, mean 5.92); ink touches the left column in 1.6% and the right in 12.5%, both sides in 0.13% (all four edges 0.13%); mean ink per column 0.000, 0.092, 0.491, 0.607, 0.612, 0.497, 0.158, 0.006; centre of mass x median 3.56 (5th to 95th percentile 3.13 to 4.09), y median 3.48 (2.81 to 4.23), centre 3.5; mean ink 0.308 (median 0.307, 5th to 95th 0.255 to 0.368, range 0.197 to 0.428); inked squares median 33 (28 to 38); full squares (16) median 6. Per digit the ink is much the same (mean 0.296 to 0.332) and the median width is 6 for every digit, **including 1s** (mean ink 0.319, 10.5 full squares, widths 4 to 6), so narrow digits were widened. That fits a digit stretched to fill a 20-pixel-wide, 32-tall box centred in the 32x32 bitmap (pixels 6 to 25 across fall in squares 1 to 6). *The rule:* the strokes' centre lines are drawn with a round pen 0.18 of the drawing's larger side wide (`PenFraction`; the pen scales with the drawing, so small and large drawings give the same image, and the pad's visible line is only for show); the ink's box (centre lines plus pen) is scaled to 32 pixels tall and separately to 20 wide, but never stretched across more than 2.25 times the vertical scale (`MaxStretch`), and its centre goes to the bitmap's centre (box centring, as the spread of the training centres of mass suggests, not centre of mass); a pixel is on when its centre is within the pen of a stroke. Marks under 0.1 pad units (`MinMark`) are scaled as if that size, so a dot stays a small blob. Strokes are in pad units (the pad's square 0..1 each way, y down), which is the only place the unit matters. *Calibration* (a simulation of the same rule over pen 0.12 to 0.2 and stretch 2 to 4, then checked in C#): a drawn "0" (an ellipse) gives mean ink 0.305, 32 inked squares, width 6; a straight "1" gives 0.305, 32 squares, width 4 (a bar about 11 pixels wide); both are nearest their own digit's mean training image (mean absolute difference); a "7" and an "8" also come out nearest their own means. A dot gives 4 squares and total ink 1.3. A "1" with a long flag is widened to the full 20 pixels and is then nearer the 3 and 9 means than the 1 mean (the real network may still read it; not checked, since the digits network is shipped later). *Interface:* `FromStrokes` returns null for no strokes or none with any length; a one-point stroke among others is a dot; non-finite coordinates throw `ArgumentException`. *Tests* (`DigitImageTests`): null cases; a vertical line touches rows 0 and 7, centre of mass 3.4 to 3.6 both ways, 2 to 4 squares wide; a "2" drawn 0.25 across in a corner and 0.8 across in the middle differ by under 0.05 per pixel (the threshold used; the rule makes them nearly identical); a dot has at most 6 inked squares, at most 3 by 2, total ink under 2.5, centred; values in 0..1 and multiples of 1/16; sizes other than 8 throw; a drawn "0" and "1" fill the height, have width within the training range, mean ink and inked squares within the training 5th to 95th percentiles (computed from the bundled set in the test), and are nearest their own digit's mean image.
