# Decisions

- **D1** Tensors store `double`, not `float`. Finite-difference gradient checks are then exact enough to trust, and the speed cost is small for scalar C#. Lesson text notes that real models use 16- or 32-bit numbers.
- **D2** A WPF-free `AIAnatomy.Presentation` project holds the view-models, so they can be unit-tested. This refines the spec's App -> Lessons chain to App -> Presentation -> Lessons.
- **D3** Pre-layer-norm blocks as in GPT-2 (`x + Attn(LN1(x))`, then `x + FF(LN2(x))`, then a final LN), with a separate (untied) output matrix, which is easier to explain as "the output layer".
- **D4** The BPE tokenizer works on characters, not bytes, so its pieces stay readable. Words are pre-split with the leading space attached (" the"), as in GPT-2.
- **D5** "Rules vs. learning" task: predict the next letter. A readable list of hand-written rules is compared with a bigram model (a table of next-letter scores) that learns from the fables in a few seconds.
- **D6** The Family and Beyond tabs exist in Stage 1, each showing a "Coming in a later stage" page that lists what it will contain.
- **D7** The training text is *Aesop's Fables* (George Fyler Townsend translation, Project Gutenberg eBook #21, public domain in the US). The Project Gutenberg header, footer and licence are removed, as their terms require when the trademark isn't used. Downloading it needs the owner's okay (asked at plan review). If it is refused, the builder writes 40 short original fables instead.
- **D8** Each forward pass works on one sequence (`[T, D]` tensors). The loss of a training batch is the mean of the B sequence losses (gradients are summed over the sequences, then divided by B). This keeps traces simple to show.
- **D9** `GradCheck.MaxRelativeError` runs on parameter copies of its inputs (so callers may pass plain tensors) and measures |analytic - numeric| / max(1, |analytic|, |numeric|), so near-zero gradients do not inflate the error. `Backward()` clears intermediate (non-leaf) gradients before propagating; leaves keep accumulating until `ZeroGrad()`.
- **D10** Tokenizer details (controller rulings, Task 5): `CharTokenizer` vocabulary is `IReadOnlyList<char>`, so only BMP characters can be in it; any other scalar (emoji) is unknown (id 0) and counts as one token. BPE words start at every space and end at the next space or newline; a newline is its own piece; merges never cross a word. BPE ties go to the pair seen first in the text. BPE ids are unknown (0), base characters in ordinal order, then one id per merge in learned order; encoding applies merges by id and rank, so two merges producing the same text stay distinct. `TextNormalizer` only turns `\r\n` and lone `\r` into `\n`.
- **D11** Transformer parts live in namespace `AIAnatomy.Models.Transformers` (plural, folder `Transformer/`): a namespace named `Transformer` clashes with the class `Transformer`. Attention biases are named `query_bias`, `key_bias`, `value_bias`; the multi-head projection is `blocks.N.attn.output` / `output_bias`; the feed-forward is `ff.in`, `ff.in_bias`, `ff.out`, `ff.out_bias`; the final norm is `final_norm`. `Transformer.Clone` builds a fresh model and copies weights in `Parameters()` order. A switched-off head returns a zero tensor, so no gradient flows to that head. The "positions removed, swap tokens 0 and 1" invariance holds exactly for one layer only (with more layers the causal mask makes positions 0 and 1 see different things), so the test uses one layer.
- **D12** Training details (Task 7). The global gradient norm is clipped to 1.0 before every Adam step (standard practice; it keeps early steps from jumping). The learning rate is constant. The loss is checked after every batch, before the Adam step, so a diverged step never changes the weights; the step is still counted and reported. Each batch sequence runs on its own thread with its own copy of the weights (slot 0 is the model itself); their gradients are added in sequence order, so results do not depend on thread timing or core count. Validation windows come from the last 10% of the text (if that is shorter than one window it grows backwards just enough to hold one), at most 32, chosen with the seed.
- **D13** `Sampling.Generate` returns only the newly written text, not the prompt. An empty prompt starts from a newline, or from the unknown token if the vocabulary has none. Probabilities are built in the order temperature, top-k, top-p, each renormalised; top-p keeps the smallest set of top choices whose total reaches p.
- **D14** Model files (Task 7): header is one JSON line (camelCase names, enums as text) with the config, vocabulary, info and every parameter's name and shape; then little-endian 64-bit floats. Loading checks format, version, config size limits, every name and shape, the exact byte count and that every number is finite; any problem is an `InvalidDataException` with a plain message. A library entry's name is the model's own name (or the file name if unreadable); saving writes through a `.tmp` file and then renames, so a failed save never leaves a half-written model. Shipped models are always returned with `IsShipped` true.
- **D15** `Ops.MatMul` loops i-k-j over spans with 4-wide vector adds and runs output rows on several threads once N*K*M exceeds 200,000. Every output element is still summed in the same order as a plain loop, so results are bit-identical with or without threads.
- **D16** Induction experiment (Task 8, ruling R16). The first design (8 random tokens then the same 8 again) is exactly periodic, so a learned-position head that looks 7 back solves it in layer 1 and no induction head forms (loss reached its floor by step 200; layer-2 scores stayed under 0.1). Training and scoring now use 17-token sequences: a random prefix, a segment of L distinct letters (L 4..8), the same segment again, random filler; prefix and filler never use the segment's letters, and the prefix length varies, so only matching by content works. `InductionScore` averages attention from second-copy position SecondStart+j to FirstStart+j+1 (positions up to 15); `PreviousTokenScore` is a diagnostic for the earlier-layer previous-token head. Choices: config unchanged (width 32, 2 layers, 2 heads, learned positions, attention-only), batch 16, learning rate 3e-3, 1,500 steps, seed 1. Result in Release: 19 s; layer-2 induction scores 0.82 and 0.90; layer-1 previous-token scores 0.40 and 0.23. The slow test runs in Release.
- **D17** Trainer windows (Task 8, R14). A window of n+1 tokens means n inputs and n targets shifted by one, so sources may give windows shorter than ContextLength+1. `CorpusBatchSource` keeps the old corpus rules and RNG order.
- **D18** Teaching toys (Task 9). Perceptron weights and bias start at zero and `Train` restarts from zero each call; one epoch is recorded per pass and training stops after the first pass with no errors. `LossSurface.Descend` returns the start point as entry 0 (steps + 1 entries). `ExpressionGraphDemo.Run` rebuilds the graph each time, so repeated runs give identical gradients. `RuleBasedWriter` has 10 rules, the last ("Otherwise, write e.") always applies; `Write` returns only the new text. `BigramModel` starts from an all-zero table (uniform), so its seed is stored but unused; it trains by full-batch `Sgd` on all adjacent pairs and generates at temperature 1. The shared 2 KB test prose moved to `TestTexts.Fable`.
- **D19** Training text and shipped models (Task 10). `content/texts/aesop-fables.txt` is Project Gutenberg eBook #21 (Townsend), body only: from the "AESOP'S FABLES" heading to the end of the last fable ("The Brazier and His Dog"); the Gutenberg header/footer/licence, contents, preface, Life of Aesop, footnotes and index are removed. Normalisation: "\n" line endings, curly quotes and apostrophes made straight, trailing spaces removed, runs of 3+ blank lines collapsed to 2. Nothing else changed, so the text keeps 3 non-ASCII characters (an em dash, "AE" and "ae" ligatures); 190,005 characters, 69 tokens with the unknown token. Source and edits are in `THIRD-PARTY-NOTICES.txt`.
- **D20** Shipped models (Task 10), built by `tools/AIAnatomy.Pretrain` in Release with seed 1. Fables model: default `TransformerConfig` (113,093 parameters), batch 8, learning rate 3e-3, **3,000 steps in 517 s** (about 0.17 s/step on this machine); train loss 1.53, **final validation loss 1.711** (below 1.9 from about step 1,600). Induction demo: `InductionExperiment.TrainAsync` with its 1,500 default steps, 21 s, best layer-2 induction score 0.904 (layer-2 head 1: 0.816); both well over the 0.6 needed. Names: "Fables model" / "Aesop's Fables (Townsend)" and "Induction demo" / "Repeated letter sequences". Both files are saved with `IsShipped` true and are under 1 MB (887 KB and 82 KB); the fables file's `ValidationLoss` is the trainer's last periodic validation (step 3,000, a multiple of 25).
- **D21** Test hygiene (Task 10, R18). `TrainerTests` and `InspectionTests` (everything that trains) share the xunit collection "Training" with parallelisation disabled, so timing assertions are not disturbed by other tests. In Debug the induction slow test is skipped with a message that names the Release command; `README.md` has a "Running the tests" section. The Models test project copies `content/**` to its output folder, like ASLCoach.
- **D22** Source citations (Task 11): `content/sources.json` holds 12 entries written from memory of the standard references; arXiv/DOI links only where certain, otherwise null (radford2019). `nostalgebraist2020` is cited as a LessWrong post and `suttonbarto2018` as the book (also used for Q-learning, not Watkins 1989). D-number: citations to be re-verified in Task 20.
- **D23** Lessons (Task 11): `sources: textbook` is reserved for standard textbook material; it is not looked up in sources.json and sets `Lesson.IsTextbookMaterial`, with `SourceIds` excluding it. The Markdown parser is lenient: headings, bullets and `$$` blocks also end a running paragraph; an unclosed `$$` is plain paragraph text; bold and italic need non-space text next to the markers, so `2 * 3 * 4` stays literal. `Order` is 1-based within a section; file names are `<nn>-<id>.md`.
- **D24** Presentation (Task 12). `MainViewModel` builds its own `LabFactory` and passes its `NavigateToLesson` as the navigate callback, so there is no construction cycle; the registry is exposed as `MainViewModel.Labs` so tests (and later App start-up) can register labs. A lesson whose lab is not registered shows `ComingLaterLabViewModel` ("This lab is being built."). `SettingsService.Save` updates `Current` even if the disk write fails (IO/permission errors are swallowed: settings are a convenience). A non-finite body size becomes 20; a blank `ActiveModelName` becomes null. Heading size is rounded half away from zero (22.4 to 22, 28 to 28, 44.8 to 45). `MainViewModel.RefreshModelEntries()` re-reads the library after saves and deletes. Selecting a lesson only refills `Lessons` when the section changed. `NavigateToLesson` throws `KeyNotFoundException` for an unknown id (from `LessonCatalog.Get`).
- **D25** Shell and controls (Task 13). Text sizes in settings are points; ThemeManager converts them to WPF pixels (1 pt = 96/72 px, as in ASLCoach) and also sets SmallFontSize (body x 0.85, at least 16 pt), SubheadingFontSize (body x 1.15) and FormulaScale (body x 1.1). Settings and Sources are pages that replace the lesson (MainViewModel `IsShowingSettings`, `IsShowingLesson`); `OpenLesson`/`ShowSection` on the already-selected item just go back to the lesson, so the lab is not recreated. `SettingsViewModel` keeps the size to whole points and saves on every change. Numbers on screen go through `Presentation.Visuals.NumberText`: `Exact` is the shortest round-trip text of the double (readouts, tooltips, legends), `Short` (3 decimals, whole numbers without decimals) is only for labels inside charts, `Tick` for axes, `Percent` two decimals; minus signs are U+2212. The heat-map ramp is the same light-to-dark blue in both themes (it is a figure); text inside a square is black or white, whichever contrasts more (at least 4.58:1). `GridCell(Row, Column)` was added to Visuals for `HeatMap.SelectedCell`. Every control draws a readout or legend with the exact value, so colour, shape (scatter groups), dash style (line series), outline plus "chosen"/"current step" tags carry meaning together. NetworkDiagram node X/Y are fractions (0..1) of its size; its text shrinks (to 60% at most) until no boxes overlap. Charts without a set height grow with the text size (at least 14 lines). MarkdownView draws bullets as text with a hanging indent because WPF list markers stayed black in the Dark theme. Lesson links and linked diagram boxes raise one bubbling routed event (`LessonNavigation.NavigateRequestedEvent`) handled once by MainWindow. `--render-png` defaults to Light at 20 pt (not the user's settings) so pictures are reproducible, uses in-memory settings so nothing is saved, never shows the window (lays out its content on its own), and draws the gallery at its full height. `--selftest all-labs` works now; `--selftest train` exits 1 with "needs the Train lab" until Task 18.
- **D26** Task 13 review fixes. The lessons list always stays in the left column; Sources, Settings (and the lab plus explanation) share columns 2 to 4. Pane scroll areas (lab, explanation, Sources, Settings, gallery) are tab stops with a focus ring (`PaneScroller` style). A keyboard-focused link becomes a solid focus-coloured block. Axis maths moved to `Presentation.Visuals.AxisTicks` (tested): ticks are computed from their index and capped at count·3 + 2; ranges are widened only when their ends are equal within 1e-9 of their size (`Widen`), and `Pad` adds 5% after that; the line chart's x axis uses `Widen` only. `NumberText.Short` keeps a single parameter (a second, optional one let `Select(NumberText.Short)` pass the index as the number of decimals); `ShortWithDecimals` is separate. Heat-map squares may grow past 96 px to fit a three-decimal number, and fall back to two decimals before leaving the number out. Network arrow labels are drawn after the boxes, moved sideways off the arrow until they touch no box. Unexpected errors (`DispatcherUnhandledException`) are appended to `%LOCALAPPDATA%\AIAnatomy\error-log.txt` and shown in a plain window ("Something went wrong: … Your settings and models are safe."); the app keeps running (diagnostic runs exit 1). `--render-png` accepts several views separated by commas (files "name-view.png"), each rendered with fresh services; radio buttons no longer use a GroupName, which linked them across windows.
- **D27** Task 14 labs (R19, N1). The Rules vs. learning lab trains the bigram model with plain gradient descent at **rate 20** in 20-step chunks (20 chunks per press of Learn, Stop between chunks). Measured on the fables: loss 4.23 (uniform) to 3.07 after one chunk, 2.52 after ten, 2.46 after twenty; at rate 3 the text still looked like noise after 20 chunks, at rate 10 it was only half-way. The loss falls on every chunk at 20 (tested). The corpus is the first 6,000 characters of the fables so a chunk stays well under a second in Debug. `BigramModel` is unchanged; a Models test checks P('h'|'t') beats uniform and is above 0.3. The Tokens lab uses a character tokenizer built from the fables (the same characters as the fables model) and a BPE learned from the whole fables text, once per merges value (cached), on a background thread after a 250 ms debounce. The Position lab reads the model's position vectors from the trace of a forward pass over a full-length dummy text, and its on-screen note says removing positions takes away the direct order signal while deeper causal models can still leak order through the mask (N1). Architecture map omits the Feed-forward box for models without feed-forward layers (the induction demo). `LabViewModel` gained `Deactivate`, `OnSeedEdited` and `WorkCompleted` (the PNG diagnostic waits for it); `HeatMap` writes only every few-th row/column label when the squares are too small; a shared `TextBox` style was added to the theme.
- **D28** Task 15 labs (R16, N3, N4). Embeddings: untrained model = fresh `Transformer` with the active config and a lab Seed that starts at the model's own `Info.Seed` (changeable, Reset restores it); one selected token is shared by both pictures. Attention toy: vectors are `DragHandle`s clamped to ±3, dragged on a new minimal `DragPlot` control (snaps to 0.05; arrow keys, Shift for bigger steps, Page Up/Down to pick a point) and typed in number boxes (commit on leaving or Enter); softmax's e^score column is shown with `Math.Exp` for display only, the weights come from `Ops.SoftmaxRows` (tested to agree). Real heat maps pass NaN above the diagonal so `HeatMap` shows "blocked". `HeatMap` gained `OutlinedCells` (heavy outline, not colour) for the R16 induction squares. `InductionExperiment.TrainAsync` gained an optional `modelCreated` callback: it is the only way to read the model while it trains; the lab's `IProgress` runs on the trainer thread between steps, measures scores every 100 steps there (safe, nothing is changing), and posts results to the UI thread; loss is charted every 10 steps. The Attention lab opens with the trained demo already shown (so the induction section is informative at once, and renders can be checked); the demo is loaded through `Library.Load` and never becomes the active model. Seed on the Attention lab picks the example sequence, the scoring sequences and the training start.

## Task 16 (Multi-head, Feed-forward, Residual labs)

- `NeuronProbe.TopContexts` gained an optional `CancellationToken` so the 20,000-character search can be cancelled when the layer or neuron changes or the lab is left.
- The feed-forward lab has no Seed box (nothing in it is random); the multi-head and residual labs likewise.
- Disabled heads keep their attention squares on screen (dimmed, titled "SWITCHED OFF"): the squares show where the head would have looked while its output is zeros.
- The layer-norm demo can show any of the N block-start norms or the final norm, so it also works for the attention-only demo model (which has no second norm).
- Array-typed properties (`Values`) cannot be bound by attribute inside a DataTemplate; the multi-head view sets them from styles.

## Task 17 (Sampling and Learning labs)

- The Learning lab shows its four parts as sections one under the other, not tabs, so nothing is hidden behind a tab and a rendered picture shows all four. Each part is its own view-model (`PerceptronPanelViewModel`, `LossPanelViewModel`, `GraphPanelViewModel`, `CrossEntropyPanelViewModel`) inside `LearningLabViewModel`; no randomness is used there, so it has no Seed box.
- Sampling lab: "Sample 100 times" restarts `SeededRandom(Seed)` each press, so the same seed gives the same counts; changing the text, a setting or the seed clears old samples and writing. The bars and score list show the 15 highest-scoring characters; the full probability array is kept for sampling. "Generate 200 characters" runs on a background thread and a changed setting drops its result.
- Perceptron: "Step one epoch" retrains from zero for one more epoch (`Perceptron.Train` always restarts), which gives the same weights as carrying on. Choosing a rule sets the epoch limit to its default (20, or 100 for XOR); changing rule or rate clears the epochs. The decision line is drawn only inside the square -0.25..1.25 (after epoch 1 of AND it lies outside, and the line text says so). The epoch table shows the last 20 epochs.
- Loss surface: 30 steps from (-4, 1.5). "Too large" is shown when the loss at the last step is above the loss at the step before (rate 0.1 exactly gives a constant w2 loss, so it is not flagged; 0.101 is). The contour plot is a new control, `ContourPlot` (shaded grid, marching-squares contour lines with values written on them, a dashed path with a square start and a diamond end). `ScatterPlot` gained a `Lines` property (dashed, named in its legend, the axes fit its end points) for the decision line.
- Expression graph: the four numbers are limited to -100..100 and not-a-number becomes 0. Node boxes show "value ... / gradient ..." on two lines, and the exact numbers are repeated in a table under the diagram.
- Cross-entropy: the places are the first N-1 tokens (each needs a next character), numbered from 1; p is read from `Sampling.Probabilities` at temperature 1; one character of text is not enough and says so.
